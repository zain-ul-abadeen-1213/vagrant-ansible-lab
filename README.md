# Vagrant Multi-VM Lab + Ansible Provisioning

A local DevOps lab that builds two Ubuntu virtual machines with Vagrant and configures them end-to-end with a single Ansible playbook — including an nginx web server serving a branded page.

## Status

✅ **Verified run — 19 November 2026.** Full playbook run completed with `failed=0` on both VMs, and a second consecutive run reported `changed=0` on both (idempotent).

## What this project does

- **Vagrant** spins up two Ubuntu 22.04 (Jammy) VMs on VirtualBox:
  - `web` — 192.168.56.10, 1 GB RAM, 1 CPU
  - `db` — 192.168.56.11, 1 GB RAM, 1 CPU
- **Ansible** (run from WSL) connects over SSH with per-host keys and applies `site.yml`:
  - **Common setup (both VMs):** apt cache update; installs `curl`, `vim`, `git`, `htop`; creates a `deploy` user.
  - **Web server setup (`web` only):** installs nginx, deploys a branded `index.html` to `/var/www/html/`, ensures nginx is started and enabled, and restarts nginx via a handler when the page changes.

## Files

| File | Purpose |
|---|---|
| `Vagrantfile` | Defines the two VMs (box, hostname, private IP, resources) |
| `inventory.ini` | Ansible inventory: `[webservers]` and `[dbservers]` groups, SSH key per host |
| `site.yml` | The playbook: common setup + web server setup + nginx restart handler |

## How to run

```bash
# On the Windows host, in the project folder:
vagrant up
vagrant status

# Inside WSL (Ubuntu), from the project folder:
ansible all -i inventory.ini -m ping
ansible-playbook -i inventory.ini site.yml

# Verify the web server:
curl http://192.168.56.10
```

## Tools used

## Notes

- The lab runs on a Windows host with Ansible driven from WSL, because the VMs need the host's full RAM (nested virtualization inside another VM would be too slow).
- SSH private keys generated by Vagrant (`.vagrant/`) are **not** committed to this repository.
